Guide for Carlo: Text Modality (CoOp)
Your task is to implement Context Optimization (CoOp). This means you will leave the vision side completely alone (relying on Mattia's base CLIP model) and focus entirely on creating learnable prompt embeddings.

1. The CoOp Implementation
In standard CLIP, the text prompt is hardcoded (e.g., "a photo of a dog"). CoOp replaces "a photo of a" with learnable vectors.
What you need to build:
Learnable Context Vectors: Create a PyTorch nn.Parameter of shape (N, D), where $N$ is the number of context tokens (e.g., 4, 8, 16) and $D$ is the embedding dimension of the CLIP text encoder (e.g., 512 for ViT-B/32).
The Custom Text Encoder: You cannot just pass strings into CLIP anymore. You must intercept the tokenization process.
	Tokenize the class name (e.g., "dog").
	Get the embedding for the "dog" token.
	Concatenate your learnable context vectors with the "dog" embedding.
	Pass this concatenated tensor through the rest of the CLIP text transformer.

2. Optimization
Since you are only training a tiny number of parameters (the context vectors), standard training loops often overfit or fail to learn properly.
	Optimizer: You will likely need a different learning rate than standard network fine-tuning (often higher, e.g., using SGD with a specific schedule).
	Freezing: You must ensure that requires_grad=False for all parameters in the CLIP text transformer; only your context vectors should have requires_grad=True.

3. Interfacing with Mattia's Code
	You will take Mattia's base model class and create a subclass (e.g., CoOpModel(BaseCLIPModel)).
	You will override Mattia's get_text_features(self, class_names) method.
	Your overridden method will generate the adapted text features using your trained context vectors and return them in the exact shape Mattia's evaluation loop expects 	(usually [num_classes, embedding_dim]).

Guide for Marco: Vision Modality (CLIP-Adapter)
Your task is to implement the CLIP-Adapter. You will leave the text side completely alone (using standard hardcoded prompts) and focus entirely on adding a lightweight adapter to the vision features.

1. The CLIP-Adapter Implementation
CLIP-Adapter does not change the internal transformer layers. It adds a small bottleneck MLP after the vision encoder and blends the new features with the original features via a residual connection.
What you need to build:
	The MLP Bottleneck: Create an nn.Module containing:A linear layer down-projecting the input dimension (e.g., 512) to a smaller dimension (e.g., 128).
	A non-linear activation (e.g., ReLU).
	A linear layer up-projecting back to the original dimension (e.g., 512).
	The Residual Blending: The final image feature $f_{final}$ is computed as:$f_{final} = \alpha \cdot \text{MLP}(f_{orig}) + (1 - \alpha) \cdot f_{orig}$where $\alpha$ is a 	blending hyperparameter (often around 0.2) and $f_{orig}$ is the original output from the frozen CLIP vision encoder.

2. Optimization
Like Carlo, you are training very few parameters compared to the full model.
	Initialization: The adapter layers must be initialized carefully so they don't destroy the pre-trained features early in training (e.g., initializing the final linear layer 	near zero).
	Freezing: You must ensure that the entire CLIP vision encoder remains frozen (requires_grad=False). Only your MLP layers should update.

3. Interfacing with Mattia's Code
You will take Mattia's base model class and create a subclass (e.g., VisionAdapterModel(BaseCLIPModel)).
You will override Mattia's get_image_features(self, images) method.
Your overridden method will:
	Pass the images through the frozen vision encoder.
	Pass those features through your MLP and apply the residual blending.
	Return the adapted features in the shape Mattia expects (usually [batch_size, embedding_dim]).
